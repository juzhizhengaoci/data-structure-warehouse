# 仓库管理系统（Warehouse Management System）

> 数据结构课程设计 · **题目 19** · 环节代码 321125
> 存储结构：**单链表（链式存储）** · 开发语言：**C (C99)** · 工具链：MinGW-w64 GCC 16.2.0

一个用纯 C 从零实现的仓库管理系统：控制台菜单式交互，覆盖货品信息维护、出入库业务、库存监控、
数据持久化，并在排序功能上做了 **5 种内部排序算法的性能实测对比**。另附一套 **后端仍为 C 语言**的
轻量 Web 界面（原生 socket HTTP 服务），无需任何第三方库。

## 二、系统架构

### 2.1 五层架构与单向依赖

模块之间**只允许上层调用下层，禁止任何反向依赖与跨层调用**；`goods.h` 是唯一的依赖根，
所有 `.c` 文件都只 `#include "goods.h"`，彼此互不引用。

```
┌──────────────────────────────────────────────────────────────────────┐
│  ⑤ 视图 / 控制层                                main.c               │
│     主菜单分发 · 删除(二次确认) · 警戒值设置 · 测试数据生成 · 启停存盘 │
└──────────────────────────────────┬───────────────────────────────────┘
                                   │  只向下调用
┌──────────────────────────────────▼───────────────────────────────────┐
│  ④ 业务层                       stock.c │ sort.c │ stat.c            │
│     入库判重累加 · 出库校验 · 查询 · 低库存警示                        │
│     5 种排序算法 + 性能对比 · 统计分析 · 多条件筛选 · 盘点表导出        │

                                   │
┌──────────────────────────────────▼───────────────────────────────────┐
│  ③ 基础服务层                          io.c │ file.c                  │

                                   │

│  ② 数据层                                         list.c             │

│     计数/汇总 · 数据域交换 · 整表释放                                 │
```

### 2.2 核心业务流程（以「入库」为例）

```
用户输入
   │
   ▼
io_input_goods()  ── 逐字段校验（编号非空 / 数量>0 / 单价≥0）
   │
   ▼
list_find_match(head, 编号, 厂家, 批次, 单价)   ← 四字段判重
   │
   ├── 命中 ──► hit->qty += 本次数量          【只累加，不新增记录】
   │
   └── 未命中 ─► list_create_node() → list_append(head, node)   【新增记录】
   │
   ▼
file_log()   写流水日志（带时间戳）
   │
   ▼
file_save()  立即写回 data.txt（防断电丢失）
```

## 四、核心数据结构

```c
typedef struct Goods {
    char   id[ID_LEN];          /* 货品编号    —— 查询 / 删除主键         */
    char   name[NAME_LEN];      /* 货品名称    —— 支持模糊查询             */
    char   factory[FACTORY_LEN];/* 生产厂家    —— 参与入库判重 / 可筛选    */
    char   batch[BATCH_LEN];    /* 批次        —— 参与入库判重             */
    int    qty;                 /* 库存数量    —— 出库不得超此值           */
    double price;               /* 单价（元）  —— 参与入库判重             */
    struct Goods *next;         /* 链指针      —— 链式存储的体现           */
} Goods;

/* 运行期统计（全局单例） */
typedef struct {
    int inCount;    /* 累计入库操作次数 */
    int outCount;   /* 累计出库操作次数 */
    int lowLimit;   /* 低库存警戒阈值（默认 20，可运行时修改） */
} SysStat;
```

**派生数据不存储：** 金额 = `qty × price` 实时计算，避免冗余字段不一致。
**浮点比较：** 判定单价是否相等时使用精度常量 `EPS = 1e-6`，规避浮点误差。

### 为什么选单链表（对照顺序表）

| 对比项 | 顺序表 | **单链表（本项目选用）** |
|---|---|---|
| 插入 / 删除 | 需移动大量元素，O(N) | **改指针即可** |
| 空间分配 | 需预估容量，扩容要整体搬迁 | **按需动态申请，节点数不受限** |
| 顺序访问 | 支持随机访问 O(1) | 只能顺序访问 O(N) |
| 存储密度 | 高 | 略低（额外存指针） |

仓库业务的核心特征是**频繁的插入与删除**（入库新增、出库维护、删除记录），且**规模不可预知**，
链表无需搬移元素、按需分配内存，与业务特征天然匹配；同时"采用链式存储结构"也是题目硬性要求。

## 五、排序算法与实测对比

`sort.c` 实现 5 种内部排序，全部**只交换节点数据域**（`list_swap_fields`），不额外申请数组，
空间复杂度均为 **O(1)**。菜单 6 → 算法 6 会在**同一份乱序数据的 5 份深拷贝**上各跑一遍，统计
「比较次数 / 移动次数」并输出对比表，保证对比公平。

| 算法 | 平均时间复杂度 | 最好 | 实现要点 |
|---|---|---|---|
| 冒泡排序 | O(N²) | O(N) | 带"本趟无交换即提前退出"优化 |
| 选择排序 | O(N²) | O(N²) | 比较次数恒定 N(N-1)/2，移动次数少 |
| 直接插入排序 | O(N²) | O(N) | **交换式实现**，避免链表断链重接；接近有序时表现好 |
| 希尔排序 | 约 O(N^1.3) | — | 间隔递减 gap = N/2, N/4, …, 1 |
| 快速排序 | O(N log N) | — | 链表分区法，取首元素为基准，递归左右半区 |

**实测数据（N = 10，按单价升序）：**

| 算法 | 比较次数 | 移动次数 |
|---|---|---|
| 冒泡排序 | 81 | 57 |
| 选择排序 | **45** | 15 |

> 理论验证：N = 10 时选择排序比较次数恒为 `N(N-1)/2 = 45`，与实测**完全一致**；
> 冒泡因提前退出优化，实际比较次数少于 N²。

**Web 版压测（`bench.c`，25 并发 / 29 请求）：**

| 指标 | 数值 |
|---|---|
| 成功响应 | 24 / 29（82.76%） |
| 平均响应时间 | 5.21 ms |
| 峰值响应时间 | 32 ms |
| 常驻内存 | 9.3 MB |
| 响应时间 < 10 ms 占比 | 70.83% |

## 六、文件格式

| 文件 | 作用 | 格式 |
|---|---|---|
| `data.txt` | 货品主数据 | `编号\|名称\|生产厂家\|批次\|数量\|单价`，每行一条，`#` 开头为注释行 |
| `log.txt` | 出入库流水日志 | `[时间戳] 操作描述`，**追加写入，永不覆盖** |
| `stock_report.txt` | 库存盘点表 | 表格明细 + 汇总行，导出生成 |

**为什么用 `|` 而不是空格分隔：** 名称、生产厂家等字段本身可能含空格，空格分隔会导致解析错位。

- **MinGW-w64 GCC**（本项目实测 16.2.0），默认路径 `D:\dev-tools\mingw64`
- 若装在其他位置，请修改 `code/build.bat` 里的 `set "PATH=D:\dev-tools\mingw64\bin;%PATH%"` 一行

```bat
cd code
```

```bash
gcc -g -Wall -std=c99 -finput-charset=UTF-8 -fexec-charset=GBK \
    main.c list.c io.c file.c stock.c sort.c stat.c -o app.exe
```

### Web 版（可选）

```bat
cd code
build_web.bat      :: 编译出 server.exe
start_web.bat      :: 启动后浏览器访问 http://localhost:8123
```

### 跑通全流程演示（覆盖所有校验点）

| 步骤 | 操作 | 预期现象 |
|---|---|---|

## 九、已知限制与改进方向

| 项 | 现状 | 改进方向 |
|---|---|---|
| 按编号查找 | 顺序遍历 O(N) | 额外建立哈希索引，均摊降至 O(1) |
| 排序稳定性 | 交换数据域会破坏稳定性 | 改为重接指针，实现稳定排序 |
| 快排最坏情况 | 取首元素为基准，有序数据退化为 O(N²) | 三数取中 / 随机基准 |
| 并发访问 | 单用户单进程，无文件锁 | 加锁或引入数据库 |
| 输入编码 | 控制台按 GBK 输出 | 统一切换 UTF-8 控制台代码页 |
