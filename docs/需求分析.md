## 一、题目原文要求

> 仓库需要对各类货品的入库、出库、库存进行管控。人工台账容易出现库存统计错误，开发仓库管理系统，
> 完成货品信息维护、出入库操作、库存监控，实现基础仓储业务模拟。
> **采用链式存储结构**建立仓库管理系统。
>
> **基础功能（必做）：**
> （1）导入：从文件导入现有货品信息，货品信息包括编号、名称、生产厂家、批次、数量、单价等（可根据实际需求自行设定）
> （2）入库：新的货品入库，并修改文件（**同一编号、生产厂商、批次及单价的产品只做数量累加，不添加记录**）
> （3）查询：根据货品编号、名称等进行查询
> （4）出库：修改库存并存入文件（注意输入的合法性）
> （5）删除：删除货品，并修改文件
> （6）排序：指定货品名称，根据单价进行排序输出
> （7）警示：当货品数量低于指定值，给出补货提示。
>
> **拓展选做功能（至少选 1 个）：**
> （1）统计货品总库存金额，统计出入库次数；
> （2）合法性校验：出库数量不能超过库存，数量不能为负数；
> （3）记录出入库流水，写入日志文件；
> （4）多条件筛选，支持按价格区间、生产厂家查询货品；
> （5）导出库存盘点表保存文件。

## 二、需求理解与业务背景

### 2.1 业务痛点
仓库日常管理中，货品信息依靠**纸质台账**或 Excel 手工登记，存在三个突出问题：

1. **查询效率低** —— 查找某个编号/名称的货品需要翻遍整本台账；
2. **库存易出错** —— 同一种货品分多次入库、多次出库后，累计数量靠人工计算，容易算错；
3. **补货不及时** —— 缺乏库存下限提醒，经常出现"要用的时候才发现没货"。

### 2.2 系统目标
用程序实现货品信息的**电子化集中管理**，替代手工台账，完成：
货品信息维护（增删改查）→ 出入库业务办理 → 库存监控与补货提醒 → 数据持久化。

### 2.3 使用者与典型场景
| 使用者 | 典型操作 |
|---|---|
| 仓库管理员 | 新货到货登记入库、领料出门办出库、盘点时查询与导出报表 |
| 管理人员 | 查看库存总金额、关注低库存清单决定是否补货 |

**典型业务流程：**
```
到货 → 入库登记（若同编号+厂家+批次+单价已存在则累加数量）
     → 系统更新库存并写入数据文件
领用 → 提出出库申请 → 系统校验数量合法性 → 扣减库存 → 写入文件
盘点 → 查询/筛选货品 → 导出盘点表 → 对低库存货品发起补货
```

## 三、功能需求

### 3.1 基础功能（必做 7 项）

| 序号 | 功能 | 需求描述 | 关键约束 / 判定标准 |
|---|---|---|---|
| F1 | **导入** | 从文件读入已有货品信息建立链表，程序启动时可自动载入 | 文件不存在时应以空仓库正常启动，并给出提示；格式错误的行应跳过而非崩溃 |
| F2 | **入库** | 录入新到货品并写入文件 | **★核心规则**：编号、生产厂家、批次、单价**四项全部相同**时**只做数量累加，不新增记录**；任一项不同则为新记录 |
| F3 | **查询** | 按货品编号查询 | 编号不存在时应提示"未找到"而非无响应 |
| F4 | | 按货品名称查询 | 需支持**模糊查询**（名称含关键字即匹配），可能返回多条 |
| F5 | **出库** | 扣减库存并写入文件 | **数量合法性**：出库数量必须 > 0，且**不能超过当前库存**；非法输入必须被拒绝并给出明确提示 |
| F6 | **删除** | 按编号删除货品记录并写入文件 | 删除前应有确认，避免误删；删除后同步更新文件 |
| F7 | **排序** | 指定排序字段（单价）排序输出 | 题目要求"根据单价排序输出"，支持升序/降序；排序后结果应可保存 |
| F8 | **警示** | 库存低于指定值时给出补货提示 | 阈值应可配置；需能列出所有低于阈值的货品清单 |

### 3.2 拓展功能（题目要求至少 1 项，本系统实现 5 项）

| 序号 | 功能 | 说明 |
|---|---|---|
| E1 | 统计货品总库存金额、出入库次数 | 总金额 = Σ(数量 × 单价)；同时统计种类数、库存总量、最高/最低库存 |
| E2 | 合法性校验 | 出库不超库存、数量非负、单价非负、编号非空 —— 在**输入层**直接拦截 |
| E3 | 出入库流水日志 | 每次入库/出库/删除/排序写入 `log.txt`，带时间戳，可追溯 |
| E4 | 多条件筛选 | 支持按**价格区间**、**生产厂家**、**低于警戒值**三种条件筛选 |
| E5 | 导出库存盘点表 | 生成 `stock_report.txt`，含明细与汇总，可直接打印用于盘点 |

## 四、数据需求

### 4.1 货品实体（核心数据结构）

| 字段 | 类型 | 长度 | 说明 | 约束 |
|---|---|---|---|---|
| 编号 id | 字符串 | 32 | 货品唯一标识 | 非空，作为查询/删除主键 |
| 名称 name | 字符串 | 100 | 货品名称 | 非空，支持模糊查询 |
| 生产厂家 factory | 字符串 | 100 | 制造商 | 参与入库判重，可用于筛选 |
| 批次 batch | 字符串 | 32 | 生产批次号 | 参与入库判重 |
| 数量 qty | 整型 | — | 当前库存量 | ≥ 0，出库不得超此值 |
| 单价 price | 双精度浮点 | — | 单价（元） | ≥ 0，参与入库判重 |
| next | 指针 | — | 链指针 | **链式存储的体现** |

**派生数据：** 金额 = 数量 × 单价（不存储，实时计算，避免数据冗余不一致）

### 4.2 持久化文件

| 文件 | 作用 | 格式 |
|---|---|---|
| `data.txt` | 货品主数据 | `编号\|名称\|生产厂家\|批次\|数量\|单价`，每行一条，`#` 开头为注释 |
| `log.txt` | 出入库流水日志 | `[时间戳] 操作类型 货品信息 数量变化`，追加写入 |
| `stock_report.txt` | 库存盘点表 | 表格形式的明细 + 汇总，导出生成 |

**选用 `|` 作为分隔符的原因：** 名称、厂家等字段可能含空格，用空格分隔会解析错位。

## 五、非功能需求

| 类别 | 要求 |
|---|---|
| **存储结构** | **必须采用链式存储**（题目硬性要求）；选型理由见第六节 |
| **容错性** | 所有输入须校验：非数字、负数、超范围、空输入、非法编号均不得导致程序崩溃 |
| **数据一致性** | 任何修改库存的操作（入库/出库/删除/排序）都必须**立即写回文件**，防止断电丢失 |
| **可用性** | 菜单式交互，操作结果有明确反馈（成功/失败原因），表格化输出便于阅读 |
| **可维护性** | 模块化设计，按功能拆分多个 `.c` / `.h` 文件（课件明确要求） |
| **性能** | 常规规模（千条级）下各操作响应应在毫秒级；排序需给出时间复杂度分析 |

## 六、数据结构选型分析（报告 2.1 可直接引用）

**结论：采用单链表（带头指针）作为核心存储结构。**

| 对比项 | 顺序表 | **单链表（选用）** |
|---|---|---|
| 插入/删除 | 需移动大量元素，O(N) | **改指针即可，O(1)（已知位置）** |
| 空间分配 | 需预先估计容量，扩容需整体搬迁 | **按需分配，节点数不受限制** |
| 存储密度 | 高 | 略低（需存指针） |
| 顺序访问 | 支持随机访问 O(1) | 只能顺序访问 O(N) |

**选型理由：**

1. **业务特征匹配** —— 货品的入库、删除、出库记录维护都是**频繁的插入与删除**操作，
   链表无需移动元素，只需调整指针，效率明显优于顺序表；
2. **规模不可预知** —— 仓库货品种类会随业务增减，链表**动态申请内存**，
   不会出现"数组开小了不够用、开大了浪费空间"的问题；
3. **记录类型异构** —— 货品包含字符串、整型、浮点等多种类型，用结构体配合链指针组织最自然；
4. **题目明确要求** —— 题目原文"**采用链式存储结构**建立仓库管理系统"，这是硬性约束。

**代价与弥补：** 链表不支持随机访问，按名称/编号查找需顺序遍历（O(N)）。
在报告第 5 章中可指出改进方向：可额外建立哈希索引将查询降至 O(1) 均摊。

## 七、模块划分（报告 2.3 对应）

| 模块文件 | 职责 | 对应需求 |
|---|---|---|
| `goods.h` | 结构体定义、常量、全部函数声明（接口层） | — |
| `list.c` | 链式存储基础操作：建节点、尾插、按编号查、**四字段判重**、按名称模糊查、删除、计数、汇总 | F1–F7 的基础 |

| `sort.c` | 五种排序算法（冒泡/选择/插入/希尔/快速）+ 性能对比 | F7 |
| `stat.c` | 库存统计、多条件筛选、盘点表导出 | E1、E4、E5 |
